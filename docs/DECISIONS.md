# DECISIONS

Short entries: **chose X over Y because Z.** Newest at the bottom.

1. **.NET 10 LTS over .NET 11** (released Nov 2026): SPEC requires LTS; clients want long support. ASP.NET/EF packages pinned to the 10.0.x line.
2. **Microsoft.Extensions.AI 10.11.x over 11.0.x:** `Microsoft.Agents.AI` 1.28.0 is built against MEAI 10.11; staying on the same line avoids version skew.
3. **NeoUI.Blazor 4.5.5 for UI components:** licence verified on NuGet and GitHub (`jimmyps/blazor-shadcn-ui`) as **MIT**, which allows commercial use; targets net10.0. No fallback needed.
4. **Embeddings stored via `CommunityToolkit.VectorData.PgVector`, schema owned by EF migrations (raw SQL for `vector(768)` and the generated `tsvector`) over `Pgvector.EntityFrameworkCore`:** the EF plugin (0.3.0) targets Npgsql EF 9; keeping EF unaware of the vector column avoids a cross-version plugin while still giving versioned, migration-managed schema.
5. **`.slnx` solution format over `.sln`:** default in the .NET 10 SDK, readable XML, fewer merge conflicts.
6. **Docker "dev toolbox" (`docker/dev.Dockerfile` + `scripts/dev.*`) in addition to the Makefile:** the dev machine has no local .NET SDK or make; the toolbox runs the same `make` targets in the official SDK image so any machine with Docker can run `make check`.
7. **xUnit v3 over xUnit v2:** current major; better async support and Testcontainers fixtures. Assertions with plain xUnit `Assert` (no extra assertion library).
8. **Scalar over Swagger UI** for the legacy API's OpenAPI viewer: `Microsoft.AspNetCore.OpenApi` generates the document; Swashbuckle is no longer in the templates.
9. **Consumer-side DTOs in `Brightline.LegacyOrders.Client` over a shared contracts assembly:** a real client team only has the existing system's HTTP/OpenAPI contract. Sharing types would couple the app to the legacy project; compatibility is proven by integration tests that run the real typed client against the real API.
10. **`AddStandardResilienceHandler` (Microsoft.Extensions.Http.Resilience) with tuned defaults** (3 retries, exponential + jitter, 5 s attempt / 20 s total timeout, circuit breaker 50 % over 30 s, 15 s break) over hand-written Polly pipelines: the standard, documented .NET pipeline; every value can be overridden under `LegacyOrders:Resilience`. POST retries are safe because return creation always carries an `Idempotency-Key`.
11. **Return numbers from a Postgres sequence (`RR-` || nextval, starting at 2291) over app-generated numbers:** unique under concurrency with no extra round trip, and matches the demo story (first return is RR-2291 after each reset).
12. **Idempotency enforced by a unique index `(customer_id, idempotency_key)` in the legacy DB, plus a race-safe retry read:** concurrent duplicates can't create two returns.
13. **Typed-client failures map to two exceptions:** `LegacyOrdersUnavailableException` (unreachable, timeouts, circuit open, 5xx after retries → the agent offers a ticket) and `LegacyOrdersRejectedException` (legacy business rule refused the write).
14. **No Sentry SDK:** CONVENTIONS lists Sentry as optional; errors are already captured as OpenTelemetry exceptions in the Aspire Dashboard (local) and Application Insights (production), so a second error pipeline adds no client value.
15. **Blazor static SSR for account pages, Interactive Server for the rest** (the .NET template pattern): sign-in must set cookies over a normal HTTP POST with antiforgery; everything else benefits from the live circuit.
16. **Chat rate limiting in the chat service, not middleware:** Blazor Server messages arrive over one SignalR connection, so per-message limits use a `PartitionedRateLimiter` keyed by client IP; HTTP endpoints (login POST) use the ASP.NET Core rate limiting middleware.
17. **PII masking with a small regex masker (`PiiMasker`) over `Microsoft.Extensions.Compliance.Redaction`:** the data we must mask is known (emails, phone numbers in free text); 30 lines are easier to audit than wiring the redaction framework through every log call. Stored tool arguments and logs pass through it.
18. **Help-centre document bytes stored in Postgres (`sources.content`) for the demo/MVP, max upload 10 MB:** keeps the free demo to one database. The production profile moves uploads to Azure Blob Storage (documented in deploy/azure) – the stateless-container rule is satisfied because no file is kept on local disk.
19. **NeoUI.Icons.Lucide 3.1.0 (MIT):** icon set matching shadcn/ui's default (Lucide); same author as NeoUI.Blazor.
20. **Testing projects use an `extern alias` for the legacy API:** .NET 10 generates a public `Program` for every web app; the alias keeps both test hosts in one project.
21. **Default chat model `gemini-3.6-flash`** (checked against the Gemini models endpoint, 27 Nov 2026: `gemini-2.5-flash` is listed but chat calls return 404; `gemini-3.7-flash` / `gemini-3.8-flash` returned 503 "high demand" on the free tier, so the demo defaults to the newest Flash that answered reliably; switch with `Ai__ChatModel`) and **`gemini-embedding-001` at 768 dimensions** (Matryoshka-trained, text-only; 768 keeps the HNSW index small). Both are config values; a guard truncates + re-normalises if an endpoint ignores the requested dimension.
22. **One SDK for every provider (OpenAI .NET SDK + `Microsoft.Extensions.AI.OpenAI`)** over `Azure.AI.OpenAI`: Gemini's compatibility endpoint, OpenAI and the Azure OpenAI v1 API (`{endpoint}/openai/v1/`, Entra ID token via `BearerTokenPolicy` + `DefaultAzureCredential`) all speak the same protocol. `Azure.AI.OpenAI` stable (2.1.0) pins an old OpenAI SDK. The `AuthenticationPolicy` constructor is flagged OPENAI001 (evaluation API); suppressed in one place with a comment.
23. **LLM resilience from the OpenAI SDK pipeline** (network timeout 60 s, `ClientRetryPolicy` with exponential backoff, 3 retries) plus an optional client-side token-bucket throttle (`Ai:MaxRequestsPerMinute`) for free-tier limits.
24. **No API key ≠ crash:** without credentials the app starts and AI calls fail with `AiNotConfiguredException` ("set Ai__Gemini__ApiKey"), so `docker compose up` works on a clean machine; ingestion jobs dead-letter immediately with that message and can be retried from the admin console.
25. **Full-text side of hybrid search uses OR semantics** (`to_tsquery('english', 'a | b | c')` built from sanitised words) over `websearch_to_tsquery` (AND): customer questions are long and natural, AND would rarely match. Ranking is `ts_rank_cd`; vector and text rankings are merged with RRF (k = 60).
26. **Deterministic chunk ids** (hash of source, version, index): a crashed ingestion job that re-runs overwrites the same rows instead of duplicating them.
27. **Shared `tests/Brightline.Testing` library** with offline fakes (feature-hashing embedding generator, scripted chat client) so unit, integration, component and eval code can run without an API key.
28. **Tools are bound to one conversation (`SupportTools` instance per `ConversationSession`) and take no customer id:** verification state is plain server memory (+ the conversation row), so a forged id in the model's arguments has no parameter to bind to (unit-tested). A chat can be verified for one customer only; 5 failed verifications lock it.
29. **Approvals with Agent Framework / MEAI `ApprovalRequiredAIFunction` + `ToolApprovalRequestContent`** (marked experimental, MEAI001 suppressed in the agent projects) and a server-built confirmation card: the card text is generated from the validated arguments after re-checking the business rules, not from the model's prose. If the re-check fails the card is "blocked" and can only be cancelled; the agent receives the policy reason.
30. **Idempotency keys derived from the conversation + business identity** (return: conversation, order, SKU; ticket: conversation, subject, category; escalation: conversation). Retries, double clicks and the model asking twice can't create duplicates; the legacy API and the tickets table both enforce the key with unique indexes.
31. **Tool results use relaxed JSON escaping:** results go to the model, never into HTML, so `<untrusted_data>` stays readable instead of `<`-escaped. The UI renders model output with Blazor's default HTML encoding.
32. **Transcripts are stored as written (staff need them), personal data is masked in logs, traces and stored tool arguments**, and conversations are purged after 90 days (`Retention:ConversationDays`).
33. **Keyword-only indexing when no AI provider is configured:** ingestion stores chunks without vectors (flagged on the source) so a fresh clone without a key still shows articles and full-text search; re-indexing after adding a key adds embeddings. Re-uploading unchanged content retries a dead ingestion job.
34. **No `<ImportMap />` in `App.razor`:** it renders an inline script that the CSP (`script-src 'self'`) blocks. Static assets are still served (and cached) by `MapStaticAssets`; NeoUI's modules load from their `_content` paths.
35. **"Waking up the demo server" = Blazor's reconnect modal:** the page itself is served by the sleeping host, so the cold-start message is shown while the SignalR connection (re)starts, with a reload link on failure.
36. **One `ChatService` per conversation, created with `ActivatorUtilities` from the circuit's services** ("New chat" starts a fresh conversation without a new circuit). The chat UI is a single `ChatPanel` reused by the Help Center and the admin "Test as customer" page.
37. **Model output is rendered with Markdig (`DisableHtml`) and a URL allow-list (http(s), relative):** raw HTML from the model or documents is escaped, `javascript:` links are neutralised; `[n]` markers become links only for citations bound to this turn's sources.
38. **Eval runs against the real stack (docker compose) with the real model**, not mocks: scenario assertions read the app database and the legacy API (reset before each scenario through its admin endpoint), which is what the SPEC asks for. Metric logic (verification/approval checks, percentiles) is unit-tested so a broken check can't silently pass.
39. **Judge model Gemini Flash-Lite** (`Eval:JudgeModel`), throttled and cached with AI.Evaluation's disk-based reporting storage: separate free-tier quota from the agent model, and re-runs only pay for changed answers.
40. **Citation validity is measured on the raw model output** (markers before cleanup), because the shipped answer is always 100% valid by construction (invalid markers are removed server-side).
41. **End-to-end test hosts both real apps on real ports (`WebApplicationFactory.UseKestrel`) with a scripted model** and drives Chromium with Playwright for .NET: deterministic and key-free, while everything except the LLM is production code (Blazor UI, agent, tools, approvals, legacy API over HTTP, Postgres). It also regenerates the README screenshots (`make screenshots`).
42. **Render free plan migrates on start-up (demo only)** because free services have no pre-deploy step; production runs migrations as a Container Apps job (`brightline-migrate`) from the deploy workflow.
43. **Azure profile: one user-assigned managed identity** for web, worker, legacy stand-in and the migration job (Key Vault Secrets User, Cognitive Services OpenAI User, Storage Blob Data Contributor); Azure OpenAI with `disableLocalAuth` (no keys); Key Vault references for every secret; web ingress with sticky sessions for Blazor circuits; a separate worker app runs the job queue.
44. **Deploy workflow gated twice** (release tag + repository variable `AZURE_DEPLOY_ENABLED=true`) so it never runs by accident; images are tagged with the release version.
45. **Demo mode enforcement in code, not just UI:** daily conversation cap in `ChatService`, per-IP chat limits, nightly legacy reset service, demo staff with the `staff` role, and uploads/re-index/delete/user creation disabled for non-admins in demo mode.

### Fixes from the independent code review (M9)
46. **Tools that need no approval are auto-approved when MEAI bundles them with a write tool in one response** (parallel tool calls): only data-changing actions ever show a card. If the order system is down while a card is built, the customer gets a blocked card offering a ticket instead of an error.
47. **Citation numbers are per conversation, never reset:** earlier numbered results stay in the model's history, so `[2]` must always mean the same source.
48. **Return idempotency key = conversation + resolved order line id** (after the server re-check), not the model's wording of the SKU. The legacy API also locks the order line (`SELECT … FOR UPDATE`) so concurrent requests with different keys can't return more than was bought.
49. **Job queue hardening:** a job whose lease expires on its last attempt is dead-lettered (no infinite crash loop); progress reports extend the lease (heartbeat); complete/fail/release are fenced on the attempt number, so a stale worker can't overwrite a newer run. A failed re-index keeps the previous version active and visible.
50. **Verification is not an oracle:** a second customer's valid order+email in an already-verified chat gets the same generic answer as a mismatch and counts as a failed attempt; the failure counter is never reset in a chat.
51. **Ticket order links are ownership-checked** against the legacy API (dropped if not the verified customer's order or if the API is down).
52. **Model links limited to this site** (relative URLs only); document titles and headings travel inside `<untrusted_data>`; the tag neutraliser also catches spaced/cased variants.
53. **Admin hardening:** "Add user" never resets an existing account; job retry is disabled for the read-only demo staff; `X-Forwarded-*` is trusted only when `Security:TrustForwardedHeaders=true` (set for Render and Container Apps, where the platform proxy is the only way in); search uses short-lived DbContexts; Software and Gift Cards are never returnable regardless of settings.
54. **Gemini 3 thought signatures handled by a pipeline policy** (`GeminiThoughtSignaturePolicy`, Gemini provider only): Gemini 3 returns `tool_calls[].extra_content.google.thought_signature` and rejects the next request with 400 if it is missing; the OpenAI SDK drops unknown fields. The policy records signatures from streamed and buffered responses by call id and adds them to outgoing assistant `tool_calls`; an unknown step (e.g. after a restart) gets Google's documented `skip_thought_signature_validator` value on its first call instead of failing. No new dependency (System.ClientModel `PipelinePolicy`). Found by the first live `make eval` run – the scripted tests cannot see wire-level fields, so a round-trip test through the real SDK with a fake HTTP handler now covers it.
55. **Gemini provider drops `seed` and `frequency_penalty`** (`GeminiOptionsChatClient`): the compatibility endpoint rejects both with 400 "Unknown name", and Microsoft.Extensions.AI.Evaluation's quality evaluators always send them, so every judge call failed. Options are copied, never mutated. Judge reproducibility comes from the evaluation response cache instead of a seed.
